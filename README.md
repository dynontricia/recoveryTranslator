# Recovery Translator

Live captions and spoken translation in English, Spanish, Polish, and French, for recovery meetings, area committees, and service assemblies. It makes meetings accessible to everyone, whatever language they speak.

## How it works

The session leader starts a session, picks its languages, and shares a QR code. Attendees open it on their phones; no account or app is needed.

For each session, the leader checks:

- **Captions:** the languages listeners can read. Whatever language someone speaks, it's captioned in every checked language.
- **Audio:** the languages listeners can also **hear** as live spoken translation. Audio implies captions.

The default is English and Spanish captions, with Spanish audio. Each caption language is one more Gemini translator on the same audio, so cost grows with the number of languages. All languages live in `languages.js`, shared by the server and the pages. Adding one means adding an entry there (its key is Gemini's language code), with its listener text checked by a native speaker.

Audio can come from:

- **This computer:** a microphone, or the computer's own sound through [BlackHole](https://existential.audio/blackhole/).
- **A Zoom meeting:** through the Recovery Translator Zoom app, using Zoom's real-time media streams (RTMS).

Translation runs on Google's Gemini Live Translate model (`gemini-3.5-live-translate-preview`).

## Using it

**Session leaders**

1. Open the site, tap **I am a session leader**, and enter your access code.
2. Check the languages (and audio languages), choose where the audio comes from, then tap **Start session**.
3. For Zoom, the easiest way is to start the session from **Apps → Recovery Translator** inside the meeting. If you start it on the website instead, you get a **Zoom link code**: enter it in the Zoom app in your meeting to connect that meeting's audio.
4. Share the QR code. **Open big display screen** shows a column per language for a projector.
5. Tap **End session** when you're done. A Zoom session also ends when the meeting's stream stops. **Pause** in the Zoom app keeps the session open.

**Listeners**

1. Scan the QR code, pick a language from the ones the session offers, and tap **Join**. The listener screen switches to that language.
2. Languages marked 🔊 can also be heard: tap the listen button.

To request an access code, contact dynontricia@gmail.com.

## Running it

```bash
npm install
npm start          # http://localhost:3000
```

Environment variables (put them in `.env` locally):

| Variable | Needed for |
|---|---|
| `ACCESS_CODE` | The original shared access code (optional; uses the server's key) |
| `GEMINI_API_KEY` | The server's own Gemini key: used with `ACCESS_CODE` and with codes you issue without a key |
| `KEY_ENCRYPTION_KEY` | Encrypts saved Gemini keys and hashes access codes. 32 random bytes, base64 (see below). Changing it makes every saved key unreadable |
| `STORE_PATH` | Where saved group settings live. On Railway, attach a volume at `/data` and set `/data/store.json` |
| `ADMIN_TOKEN` | Admin API below (24+ random characters) |
| `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` | Zoom app authorization |
| `ZM_RTMS_CLIENT`, `ZM_RTMS_SECRET` | Joining Zoom audio streams (read by `@zoom/rtms`) |
| `ZOOM_WEBHOOK_SECRET_TOKEN` | Verifying the Zoom webhook URL |

Zoom app settings point at:

- Home URL: `/zoom-app`
- OAuth redirect: `/zoom/oauth/callback`
- Event webhook (RTMS started/stopped): `/zoom/rtms-webhook`
- Deauthorization notification endpoint (app removed): `/zoom/deauthorize`

Make a `KEY_ENCRYPTION_KEY` or `ADMIN_TOKEN` with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## Group settings and access codes

A group can start sessions in two ways:

- **Its own Gemini key, saved from the Zoom app.** In the panel, **Settings → Save key**. The server checks the key with Google, encrypts it (AES-256-GCM), and links it to that Zoom user. After that, the group starts sessions in Zoom with no code. The first save also shows a **website access code** once, so the group can use the same key on the website. Removing the app from Zoom deletes the record.
- **An access code you issue**, with the group's key or with the server's key.

Saved settings live in one JSON file (`store.js` is the only code that touches it). The file never holds a key in plain text, an access code, or a raw Zoom user ID: keys are encrypted, and codes and Zoom user IDs are stored as HMAC hashes.

**Admin API.** Send `Authorization: Bearer $ADMIN_TOKEN` with every request:

```bash
# List groups (never shows keys or codes)
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" https://app.recoverytranslator.com/admin/groups

# New access code using the server's key -- the code is shown only in this response
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"label":"Area committee"}' https://app.recoverytranslator.com/admin/groups

# New access code using the group's own key
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"label":"Grupo Esperanza","geminiKey":"AIza..."}' https://app.recoverytranslator.com/admin/groups

# Turn a group off or on, or delete it
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://app.recoverytranslator.com/admin/groups/<id>/disable
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://app.recoverytranslator.com/admin/groups/<id>/enable
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://app.recoverytranslator.com/admin/groups/<id>/delete
```

Ten wrong access codes (or admin tokens) from one address lock it out for 15 minutes.

Sessions live in memory only, so restarting the server ends every session.

Every Zoom webhook request is checked against Zoom's signature (`x-zm-signature`) and rejected if it's missing, wrong, or more than 5 minutes old. Zoom OAuth tokens are used only to complete installation and are never stored.

Each Zoom session belongs to one meeting. When Zoom opens the panel, it sends a signed, encrypted `x-zoom-app-context` header naming the user and meeting. The server gives the panel a short-lived token for that meeting, and a meeting's audio stream (`meeting_uuid` in the RTMS webhook) only attaches to a session from the same meeting. Two groups captioning at the same time never see or hear each other's sessions.

**Viewer mode.** Zoom's signed context also says each person's meeting role (`attendrole`). Hosts and co-hosts get the full panel. Everyone else (attendees, panelists, guests who haven't installed the app, or an unexpected or missing role) gets a captions-only viewer: the session's languages, live captions, and text size, with no access code, start form, settings, or controls. The server enforces this on every call, not just the page. The host's **Invite everyone to view captions in Zoom** button uses Zoom's `sendAppInvitationToAllParticipants`.

Only the session's own leader can pause, connect, or end it: the host or a co-host in the panel in the same meeting, or the browser that started it (it holds a secret leader token). The session code that listeners use is not enough. Logs show meetings only as a short one-way hash, such as `meeting #1a1098c1`.

## Privacy

No personal accounts or names are collected, and no audio, captions, or translations are stored on the server. Groups' saved Gemini keys are stored encrypted (see above). With the server's key, or a group key from a Google project with billing turned on, audio goes to the **paid** Gemini API, so Google does not use it to improve its products. Free-tier keys don't get that promise, so the docs tell groups to turn billing on. Google keeps prompts and responses for up to 55 days, only for abuse monitoring. Server logs hold only session codes, connection events and Zoom stream IDs, never speech or caption text. The full policy is under **Privacy Policy** on the site (`index.html`).
